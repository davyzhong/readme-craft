# readme-craft 全面审查（2026-09-25）

## 结论摘要

核心产品范围已经成形：方法论、按类型模板、Agent Skill、确定性 CLI、GitHub Action、本地评分页和批量审计围绕同一 README 工作流。审查发现的两项高优先级封存门槛仍需所有者决策：发布 workflow 的 tag/version/channel 防护，以及公开 Git 历史与许可证归属的最终处置。故当前建议为**暂不宣布项目已封存**；可按维护冻结候选处理，待门槛明确后归档为已封存。

本轮在既定范围内修复了本地预览路径边界、Skill 覆盖操作的符号链接安全、review YAML 类型校验及多处过期/私有项目文案。没有改 CI/CD、发布包、删除文件或改写历史。

## 评估边界与证据

- 评估仓库当前可访问源码、测试、规则、模板、包清单、Action、Web、公开文档、可访问 Git refs 与忽略的私有归档索引。
- 竞品表是按类别抽样的可验证市场地图，不宣称穷尽所有同类工具；快照日期为 2026-09-25。链接到官方仓库、产品文档或论文。
- 结论标签：**已验证**表示可由代码/测试/公开资料复核；**判断**表示基于比较做出的产品判断；**待所有者决定**表示仅凭当前证据不能代替所有者授权或意图。
- 内部项目名、本地路径、原始私有审计与历史元数据不在公开报告展开，目录与状态见 `.local/archive/README.md`（仅本地可见）。

| markdownlint、Vale、alex、remark-lint 等 | Markdown 语法/风格/包容性 lint | 可组合的底层替代；一般不提供 README 项目证据、评分口径与项目类型规则的整套流程 |

**市场空白判断（非唯一性声明）**：readme-craft 的组合特征是规则单一事实源、确定性与 agent-review 分层、N/A/未核验口径、按项目类型分支，以及 Skill/CLI/Action/Web 多入口。竞品中存在重叠能力，因此不能据此声称“唯一”或“无竞品”。最需要吸收的是可配置规则、审查解释、批量治理报告与验证证据；这些可作为既有流程的改进，不构成扩展为通用文档平台的理由。

竞品来源的能力描述均按 2026-09-25 可访问的官方仓库/文档记录。readme-doctor 的引用来自其公开包页，公开维护信号偏弱，未把其视为活跃产品的强证据；`github-readme-generator` 与 `readme-crafter-skill` 仅代表可见的 Agent Skill 样本。GitHub 仓库/市场检索存在命名差异和索引局限，故未声称逐一枚举全网所有工具。通用 Markdown lint 工具列为替代层而非 README 方法论竞品。

## 本轮修复

- 更新竞品比较为有日期的代表性类别地图，去除未证实的排他性市场主张。
- 移除公开树中的私有示例项目标识和私有本地审计指针，修正死 fixture 引用及过时产品文案。
- 修复本地预览服务器路径边界、Skill 覆盖的 symlink 边界、review YAML 的类型健壮性，并补回归测试。
- 增加项目公开时间线、归档入口和未来中期冻结标准。
- `.local/` 原始资料与提交日志的归档计划见私有索引；不公开、不入 npm 包。
